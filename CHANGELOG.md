# Changelog

All notable changes to this project will be documented in this file. Future
entries are generated by [`git-cliff`](https://git-cliff.org/) from
conventional commit messages (see [`cliff.toml`](cliff.toml)); this file
includes a curated entry for the hardening cycle that produced 0.3.0-rc.

## [0.3.0-rc.5] — 2026-06-09

### Fleet scale

- **Opt-in connect-establishment concurrency cap.** New
  `set_connect_concurrency(n)` / `connect_concurrency()` (Rust + Python) bound
  how many devices establish a connection (TCP connect + session-key handshake)
  at once — a connect-storm guard for fleets that come online or reconnect en
  masse. The default is unbounded (unchanged behavior); the permit is held only
  across establishment and released on success/failure/timeout, so a fleet
  larger than the cap cannot deadlock. Applies to initial connect and reconnect.
- **Fleet-scale regression test**: 1000 concurrent device connections, mocks
  split across processes, run as a dedicated CI step. Also asserts the no-cap
  deadlock-freedom property (1000 devices connect under a cap of 50).

## [0.3.0-rc.4] — 2026-06-08

Protocol-parity hardening against the tinytuya reference, plus the
mock-based end-to-end coverage that closes the pre-stable real-device
verification gap.

### Protocol (payload parity with tinytuya)

A new parity harness generates tinytuya's payload for every
version × dev_type × command × data combination and asserts rustuya
produces the identical command code and JSON (210/210 cases match). It
surfaced three wire-level divergences, now fixed:

- **device22 is a dialect layered on the base version**, not a
  replacement. `ProtocolDev22` now delegates every command to the base
  protocol except the status query, so v3.4/v3.5 device22 keeps the
  modern `Control` envelope instead of a legacy shape.
- **v3.2 is always device22** (matching tinytuya's `set_version(3.2)`).
  The status query now goes out as `ControlNew` (0x0d); the previous
  half-applied path sent `DpQuery` (0x0a), which a real v3.2 device
  rejects.
- **`LanExtStream` is version-independent** — the legacy path wrongly
  flattened the body onto the root; it now wraps under `data` for every
  version (`{reqType, data:{…}}`), matching tinytuya.

### Testing

- **tuyamock integration tests** ([`python/tests/test_tuyamock_integration.py`](python/tests/test_tuyamock_integration.py),
  CI `python-integration` job): drive the real client against the
  [tuyamock](https://pypi.org/project/tuyamock/) device emulator across
  v3.1–v3.5 and the device22 dialect — connection, framing, encryption,
  and the v3.4/v3.5 session-key handshake end-to-end, no hardware. This
  replaces the outstanding real-device verification milestone.
- **Listener Arc-bookkeeping tests de-flaked** (~15% → 0%) by building
  test devices without the background connection actor, removing a
  cross-thread `strong_count` race instead of polling around it.

### Python

- `Device(...)` gained a `port` keyword argument (forwards to the Rust
  builder's `.port()`), needed to point the client at a mock on an
  arbitrary port.

## [0.3.0-rc.3] — 2026-05-25

A small follow-up on top of `0.3.0-rc.2`, all in the Scanner subsystem.
Triggered by an active/passive scan behavior audit; nothing was observed
to fail in field testing, but two setter papercuts could surprise a
caller that reconfigured the singleton at runtime.

### Scanner

- **`set_ports` now removes obsolete ports**. Previously it only added
  the diff, so calling `set_ports(&[6667])` after the default
  `[6666, 6667, 7000]` silently kept the original three sockets alive
  instead of narrowing the listen set. The setter now computes a
  symmetric diff: missing ports are added, removed ports have their
  receiver task aborted and socket dropped. The pure helper
  `compute_port_diff` is covered by 5 unit tests.
- **`set_bind_address` now rebinds existing sockets**. Previously the
  new address was stored in `ScannerState` but only took effect on the
  next listener (re)start. Calling it on a running scanner did nothing
  visible. The setter now tears down each receiver task, rebinds its
  socket at the new address, and re-spawns; the dispatcher task and
  `packet_tx` are preserved across the swap so in-flight discovery is
  not interrupted.
- **Listener startup is serialized**. `ensure_passive_listener` now
  acquires a `parking_lot::Mutex<()>` startup guard before reconciling
  ports, so two concurrent first-time callers cannot both observe
  "dispatcher absent" and race to spawn it. Helper-pattern wrapping
  (`reconcile_listener_locked`) keeps the non-reentrant lock from
  deadlocking when setters call into reconciliation while already
  holding the guard.
- **Packet dispatch capacity raised**. `PACKET_CHANNEL_CAPACITY`
  promoted to a named constant and raised `100` → `1024`. The previous
  value left no headroom for fleet-scale bursts; the cost is one
  channel allocation at first listener start.
- **Discovery loop post-MAX simplification**. After the configured
  `MAX_BROADCASTS` are sent, the loop now drops the prior
  "wait one final receive-margin tick then exit" branch. Timing is
  identical (the receive margin was already accounted for in the
  total scan timeout); the change just removes one piece of state and
  one branch from the hot path.

### Documentation

- `docs/technical-notes.md` Scanner section expanded with the
  active/passive scan design intent, an ASCII flow diagram of the
  packet path (socket → receiver tasks → dispatcher → consumers), the
  reasoning behind the cooldown asymmetry between active and passive
  shutdown paths, and notes on the startup guard / packet capacity /
  loop simplification listed above.
- `docs/rust-api.md` `DeviceBuilder` example: `.run()` → `.build()`
  (the deprecated alias was removed in rc.2 and the doc was left
  pointing at it).

## [0.3.0-rc.2] — 2026-05-24

A small follow-up on top of `0.3.0-rc.1` that:

- splits `device.rs` into a `device/` module (no behavior change), so the
  surface is easier to navigate before stable;
- locks in a thick regression-test baseline for the listener subsystem
  (Arc accounting, drop/stop lifecycle, concurrent fan-out, broadcast lag);
- removes all `#[deprecated]` aliases left over from the rc.1 cycle
  (`DeviceBuilder::run` / `sync::DeviceBuilder::run`, the implicit
  `Deref<Target = AsyncDevice>` on `sync::Device`, the top-level FFI
  re-exports `DeviceCommand` / `SubDeviceCommand` / `SyncRequest`);
- collapses `ScannerBuilder` into the `Scanner` singleton — see Scanner
  section below — and stops caching the local-IP lookup, so a host whose
  IP changes mid-process no longer stamps stale addresses into v3.5
  discovery broadcasts;
- fixes three small Device papercuts surfaced while writing the technical
  notes (see Device section below);
- adds [`docs/technical-notes.md`](docs/technical-notes.md), a maintainer-
  facing tour of lifecycles, channels, timers, backoff math, the listener
  model, and the small decisions the layer overview glosses over.

### Scanner

- `ScannerBuilder` (and `sync::ScannerBuilder`) are **removed**. They
  produced an independent `Scanner` instance that bound the same UDP ports
  as the global singleton with `SO_REUSEADDR` — under unicast UDP that
  meant only one of the two sockets received each packet, nondeterministi-
  cally. The builder was unused outside the library itself and silently
  conflicted with the global. Configuration now goes through setters on
  the singleton (`Scanner::get().set_timeout(...)` / `set_ports(...)` /
  `set_bind_address(...)`); the setters take `&self` because `timeout`,
  `bind_addr`, and `ports` are now interior-mutable fields on
  `ScannerState`. The sync mirror gained the same setters.
- The process-wide `LOCAL_IP_CACHE` (a `OnceLock<Option<String>>` around
  `discover_local_ip_blocking`) is **removed**. It froze the host's local
  IP at first call, so any later IP change (DHCP renewal, WiFi switch,
  VPN up/down, container restart) silently stamped the wrong "ip" into
  v3.5 (port 7000) discovery broadcasts for the rest of the process'
  lifetime. The lookup is a kernel route query, sub-millisecond, and only
  runs from `send_discovery_broadcast` at most a few times per active
  scan — so the saved cost was negligible compared to the staleness risk.
  Older protocols (v3.1–v3.4) never carried the local IP in the discovery
  payload and were unaffected either way.

### Device

- **`persist=false` burst collapse**. When a `persist=false` device was
  unreachable and the user fired N requests rapidly, each request got
  its own full exponential backoff sleep, sequentially. Request #10
  could wait hours. New design: on each retry failure we set a
  `cooldown_until = now + backoff` window; requests arriving inside the
  window are rejected immediately as `Offline`; requests arriving after
  the window get an immediate retry with no extra sleep. SYN-storm
  protection preserved, latency for queued requests drops from "minutes
  to hours" to "milliseconds". `ConnectNow` still bypasses the cooldown.
- **Single-device initial-connect jitter**. `Device::new` always slept
  0–5s before its first connect to spread out thundering-herd reconnects
  for fleets of hundreds-to-thousands of devices (the original Python-
  heavy-fleet use case). For a single-device caller this was pure
  latency for no benefit. A new global atomic tracks the last device-
  construction time; if no other device was constructed within 100ms,
  the new device gets zero jitter. Bursty multi-device startup is
  unchanged.
- **`Device::receive()` surfaces broadcast lag**. Previously it
  silently swallowed `RecvError::Lagged(n)` and waited for the next
  message; a state-tracking consumer would never know it had missed
  any. Now returns the new
  `TuyaError::BroadcastLagged { skipped: u64 }` (code `ERR_STATE`) so
  the caller can re-query state or accept the gap.
  `Device::listener()` continues to emit a synthetic `listener_lagged`
  event on its stream — same observability, shape matched to a stream.

### Documentation

- `docs/technical-notes.md` corrected: heartbeats fire ~every 10s of
  idleness (not "5–10s" — the 5s tick alternates skip/fire under the 7s
  minimum gap). Also adds an operational note that the "3 consecutive
  successes" reset rule produces a backoff plateau for ~80%-reliable
  devices, which is intentional but non-obvious.

## [0.3.0-rc.1] — 2026-05-23

A defense-in-depth hardening pass over the 0.2.x line. None of the items
below were observed to fail in production; they protect against edge cases
under stop/restart, runtime reconfiguration, narrow races, and unusual call
patterns. The library's happy-path API surface and on-the-wire behavior are
unchanged.

### Correctness

- **Scanner**: re-creatable `CancellationToken` so `stop_passive_listener()`
  no longer permanently disables the scanner on the next start. (M1.1)
- **Scanner**: single long-lived `mpsc` shared by all receiver tasks; calling
  `set_ports()` after start now actually delivers packets on the newly added
  port. (M1.2)
- **Scanner**: dispatcher `JoinHandle` is tracked alongside receivers so
  `Drop` cleans it up. (M1.3)
- **Device**: discovery notifications now ride a `tokio::sync::watch` channel
  — `Notify::notified()` had a narrow re-subscribe race that could lose a
  publish between two awaits. (M1.4)
- **Device**: `persist=false` retry loop applies exponential backoff between
  user-triggered retries, so rapid commands against an unreachable device no
  longer produce a TCP SYN storm. (M1.5)
- **Device**: `scan_for_prefix` returns `Err(KeyOrVersionError)` instead of
  `Ok(None)` after 1024 garbage bytes; the reader no longer spins silently on
  a desynced stream. (M1.6)
- **Scanner**: `DEFAULT_SCAN_TIMEOUT` is now derived from
  `BROADCAST_INTERVAL`, `MAX_BROADCASTS`, and `RECEIVE_MARGIN` with a
  regression test pinning the invariant. (M1.8)
- **Device**: `close()` / `stop()` use a dedicated `Notify` channel and
  short-circuit any queued user request. The old mpsc `Disconnect` path is
  removed. (M2.1)
- **Device**: `get_cipher` uses read-then-upgrade locking; reader and writer
  halves of the same connection no longer serialize on a write lock. (M2.3)
- **Scanner**: `discover_local_ip` tries multiple non-routing destinations
  (`8.8.8.8`, `255.255.255.255`, TEST-NET-3) and caches the result process-
  wide so the lookup works on air-gapped LANs and never runs more than once.
  (M2.4 / M2.5)
- **Scanner**: `active_scanning` uses `compare_exchange` so two concurrent
  `scan_stream()` callers cannot both spawn discovery loops. (M2.6)
- **Device**: `get_timestamp` logs a warning on clock skew rather than
  silently sending `t=0`. (M2.9)
- **Device**: `seqno` increment uses `wrapping_add` (panic-free in debug; the
  field is informational on the wire — Tuya's LAN protocol does not provide
  request/response correlation, see the inline note in `process_command`).
  (M2.8)

### Synchronous wrapper

- Calling the sync API from inside a tokio runtime now returns a clear
  `TuyaError::io_other` instead of panicking inside `blocking_send`. (M1.7)
- New synchronous shortcuts `Device::fire_close` / `Device::fire_stop` and
  their sync mirrors bypass the worker channel so shutdown can't queue
  behind in-flight commands.
- `sync::Device::listener` now returns `Receiver<Result<TuyaMessage>>` so
  consumers can distinguish a delivered message from a broadcast lag or
  device-offline synthetic. (M3.6)
- `sync::Device` mirrors every async getter/setter (`dev_type`, `version`,
  `timeout`, `port`, `persist`, `nowait`, `is_connected`, `is_stopped`,
  `address`, `config_address`, plus their `set_*` counterparts and
  `connect_now`). The implicit `Deref<Target = AsyncDevice>` is
  **deprecated**; use the explicit `as_async()` accessor instead. (M3.1)

### API hygiene

- `Scanner::timeout`, `bind_addr`, `ports` are now private; mutation must go
  through `set_timeout` / `set_bind_address` / `set_ports`, which run the
  listener reconciliation. (M3.3)
- `DeviceBuilder::run` and `sync::DeviceBuilder::run` are now **deprecated**
  aliases for `build()` — the conventional builder terminal verb. (M3.4)
- `Scanner::discover_device_internal` is now `pub(crate)`. (M3.7)
- The FFI surface used by the Python bindings (`DeviceCommand`,
  `SubDeviceCommand`, `SyncRequest`) is now reachable via
  `rustuya::sync::internal::*` in addition to the top-level paths; the
  top-level paths stay for backward compatibility and will be removed in a
  future minor release. (M3.2)

### Refactoring

- Response-matching logic extracted from `process_command` into the pure
  `match_response` function with full unit-test coverage. (M4.1)
- Per-version protocol `generate_payload` arms factored into shared helpers
  (`apply_update_dps`, `strip_status_heartbeat`, `modern_control_envelope`,
  `modern_lan_ext_stream`, `legacy_lan_ext_stream`) in `protocol/mod.rs`.
  (M4.2)
- Empty `Drop for Device` removed. (M4.3)
- Unused `_prefix` parameter dropped from `decrypt_and_clean_payload`. (M4.4)
- `wait_for_response!` macro replaced with a generic `wait_for_response`
  function. (M4.6)
- Sync worker channel capacities centralized as `CHAN_WORKER_COMMAND_CAPACITY`.
  (M4.7)
- `hex` crate dependency dropped — replaced with a 10-line inline
  `crypto::hex_encode`. (M4.8)

### Documentation

- Rustdoc on `Device::status` and `Device::request` documents the
  request/response correlation gap (Tuya's LAN protocol is structurally
  fire-and-forget; seqno matching is impossible). (M6.3)
- New "Choosing sync vs async" guide in [lib.rs](src/lib.rs) and a panic-
  avoidance note in the [`sync`](src/sync.rs) module. (M6.1 / M6.2)

### Tests

- 24 → 36+ tests covering: lifecycle (`fire_close` / `fire_stop` /
  `close_notify` / drop), runtime-context guard, scanner timing invariant,
  packet_tx lifecycle, dispatch_packet routing, watch-channel migration,
  `match_response` decision table, concurrent active-scanning claim,
  `ConnectionState` invariants.

### Deferred to a follow-up

- **M5.1**: `trait ScannerHandle` / `trait Clock` / generic
  `AsyncRead + AsyncWrite` plumbing — these are most useful as the substrate
  for mock-TCP integration tests; the trait shapes should be designed
  together with those tests rather than guessed up-front.
- **M5.2 (partial)**: in-process mock-TCP server replaying v3.3/v3.4/v3.5
  device traffic for handshake / session-key / dev22 fallback paths.
- **M6.4**: `log` → `tracing` migration. ~50 call sites plus a parallel
  change in the bindings crate; scoped as its own PR.
